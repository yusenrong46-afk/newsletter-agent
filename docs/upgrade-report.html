1 · Reading mail

The first scan is 6.5× faster

4.5 min estimated first scan of 5,000 real emails (was about 28 min)

Before, the app asked Gmail for one email and waited for the answer before asking for the next. Now it keeps eight requests going at once, and still uses the answers in their original order, so the report is exactly the same. If Gmail asks it to slow down, it drops to one at a time instead of failing.

Measured: 1,000 emails with 30 ms per read took 31.8 s before and 4.9 s after. A full run that also reads text and labels 300 emails: 19.1 s → 3.2 s. The real-mailbox estimate assumes Gmail's usual 3 reads per second. Each lane shows 40 of the emails, at the measured relative speed.

2 · Keeping notes

8.4× less written to disk on a big mailbox

The app remembers each email's headers so it never reads them twice. Version 0.1 kept that memory in one big file and rewrote the whole file after every 500 emails, so the work grew with the square of your mailbox. Version 0.2 keeps it in a small database and only adds the new rows. The bigger the mailbox, the bigger the difference.

v0.1 v0.2

Bytes passed to the disk during one first scan, measured by the operating system. Upgrading keeps everything already learned: a real v0.1 data folder moved to v0.2 with 0 emails re-read and 0 model calls. A hard kill in the middle of a scan leaves the database intact, and the next run picks up where it stopped.

3 · Code health

Every lint and type problem fixed, and checked on every change

A linter catches sloppy or risky code; a type checker catches parts that don't fit together. Both now run in CI, so a mistake like a misspelled name or a forgotten "nothing" value is caught before it ships.

107 0lint findings
20 0type errors
94 207tests, all passing, all offline

Same settings for both versions: ruff 0.17.6 --line-length 120 --select E,F,W,B,UP,SIM,I --target-version py311 --config lint.isort.known-first-party = ['newsletter_agent', 'helpers']; mypy 2.4.1 --python-version 3.11 --check-untyped-defs --ignore-missing-imports. New tests cover failures on purpose: a hard kill mid-scan, a corrupt database, rate limits, Ctrl-C with reads in flight, invented answers from the model, and failed scheduler installs.

4 · Where it runs

Now on Windows and Linux too, with daily briefings everywhere

Version 0.1 used a Unix-only lock, so it could not even start on Windows, and only Macs could schedule the daily briefing. Now each system uses its own scheduler. A bug is fixed too: if installing the schedule failed, v0.1 still switched on automatic approval.
